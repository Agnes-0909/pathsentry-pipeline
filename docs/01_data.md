# 01 · 数据收集与任务定义

## 1. 任务与类别体系（v1）

### 1.1 检测类别（12 类）

| 分组 | 类别 | 说明 |
|---|---|---|
| 动态 | person（行人）, pet（猫狗） | 重点类别，标注全身框 |
| 静态障碍 | cone（锥桶）, chair_leg（椅腿/桌腿）, flowerpot（花盆）, rail（栏杆/围栏）, vehicle（车辆/玩具车）, toy（散落玩具/杂物） | |
| 地面风险 | wire（电线/线缆）, pit（坑洞/凹陷）, step_edge（台阶边缘/落差） | 细长/低对比，长尾重点补采 |
| 兜底 | obstacle_other（其他障碍物） | 不可归类的明显障碍 |

标注规则要点：
- 框紧贴可见轮廓，遮挡 >70% 且难辨认的不标；
- 截断目标（贴图像边缘）正常标注，标记 `truncated=1`；
- 远处 <12×12 px 的目标不标（训练时自动当忽略区处理可选）；
- 每帧记录场景标签（grass / indoor / cement / backlight / dusk / wet …）便于分层评测。

### 1.2 分割类别（4 类）

| 类别 | 含义 |
|---|---|
| drivable_road | 当前小车可通过的路面/平整地面 |
| grass | 草地（对割草机型任务是可行驶，本任务默认不可行驶，按车定义） |
| boundary | 可行驶区与不可行驶区交界（路缘、边界线）|
| non_drivable | 其余（墙体、障碍物、天空等） |

> 可行驶性以**本小车的通过能力**为准（轮距、越障高度），在采集前用小车实地标定一次"哪些地面过得去"，写进标注手册。

## 2. 开源数据集选型

| 数据集 | 内容 | 用途 |
|---|---|---|
| **RELLIS-3D** | 13.6k 帧多模态（RGB/深度/激光），越野场景 20 类语义分割 | 分割分支预训练主力 |
| **RUGD** | 7.5k 帧越野（公园/小径/草地），RGB 分割标注 | 分割预训练补充 |
| **Cityscapes**（可只用于预训练） | 城市街道精细分割 | 引入 road/sidewalk 先验 |
| **KITTI / BDD100K 检测子集** | 行人/车辆检测 | 检测分支预训练（也可直接用 COCO 预训练权重替代） |
| **Lost and Found** | 街道小障碍物检测 | 长尾"地面风险"类参考 |

使用原则：
1. 开源数据只做**预训练域**，评测一律用本地测试集（避免域偏移虚高）；
2. 类别映射表单独维护（如 RELLIS `dirt road/favorite road → drivable_road`，`vegetation → grass`），映射脚本进仓库；
3. 从开源数据采样 ≤30% 混入微调阶段，防止本地数据被淹没。

## 3. 本地数据采集规范

### 3.1 设备与录制
- 双目同步触发，左右目时间戳差 <1ms；分辨率 1280×720，30fps；
- 同时录 IMU（后续时序滤波/困难帧对齐用）；
- 存储格式：左目 `left/xxxxx.png`（PNG 无损），右目 `right/xxxxx.png`，标定文件（内参/外参/畸变）随每个采集批次更新；
- 每次采集前后拍标定板，做一次 stereo 校验（重投影误差 <0.5px 才入库）。

### 3.2 采集矩阵（分层覆盖）

| 维度 | 取值 |
|---|---|
| 场景 | 草地 / 水泥路 / 室内 / 混合边界 |
| 光照 | 正午顺光、强逆光、黄昏、阴天、（可选）夜间 |
| 天气 | 干燥 / 雨后湿地 / 落叶覆盖 |
| 障碍密度 | 空旷 / 正常 / 密集摆放 |

计划总量：**原始 ≥50k 帧 → 去冗余抽帧后 ≥5k 帧进入标注**（抽帧规则见 3.3）。刻意补采三类长尾：电线、坑洞、逆光下的行人。

### 3.3 去冗余抽帧
- 相邻帧 SSIM/直方图相似度聚类，每簇保留 1~3 帧；
- 使用轻量检测模型（预标注分支的中间产物即可）打分，保留"出现新目标/高不确定性"的帧，形成困难场景过采样。

### 3.4 数据集划分与治理
- 按**采集时段/路线**划分 train/val/test（8:1:1），禁止随机按帧切分（同路线相邻帧泄漏）；
- test 集人工精标（金标准），val 可用预标注+人工修正；
- 目录：`data/raw/`、`data/processed/`、`data/annotations/{coco,seg}/`、`data/splits/`；
- 标注格式：检测 COCO JSON；分割单通道 PNG 调色板 mask；
- 版本化：每次数据/标注变更生成 `dataset_vX` 清单（帧数、类别分布、场景分布）。

## 4. 评价方法

- **采集质量**：场景矩阵覆盖率表格；每类目标实例数分布（长尾类每类 ≥300 实例为达标线）；
- **标注质量**：双人交叉标注 ≥200 帧计算一致率（检测 mAP@IoU0.5 互相评、分割 mIoU），目标 ≥90%；
- **金标准测试集**：≥500 帧全人工精标 + 场景分层标签，供后续所有阶段统一评测。
