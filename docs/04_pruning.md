# 04 · 模型剪枝（结构化通道剪枝）

## 1. 目标与约束

- FLOPs 降 **≥35%**（参数量随之下降），为量化后的 BPU 帧率留余量；
- 精度损失硬约束：mAP@0.5 掉点 ≤2 个点、mIoU 掉点 ≤3 个点（相对 FP32 基线）；
- 采用**结构化（通道级）剪枝**：产出稠密小模型，ONNX 导出与地平线工具链完全兼容——这是相对非结构化稀疏的关键工程决策。

## 2. 技术路线：Torch-Pruning + 迭代剪枝恢复

工具：[Torch-Pruning](https://github.com/VainF/Torch-Pruning)（依赖图自动分组耦合通道，支持 YOLO 系列官方示例）。

流程（迭代式，比一次剪到位稳）：

```
基线 FP32 模型
  └─ 循环 k=1..K (K≈5~8 轮，每轮剪 8%~12%)
       1. importance 评分：对每组耦合通道算重要性
          （主线：L2 范数；对照：Taylor 展开一阶梯度重要性）
       2. 按全局排序剪除目标比例通道，物理移除（model 变小）
       3. 恢复微调：本地域数据 10~20 epoch，lr=基线 1/10
       4. val 集评测，记录 (稀疏率, mAP, mIoU, FLOPs) 曲线
  └─ 达到精度边界即停，输出选定稀疏率的剪枝模型
```

要点：
- **恢复微调数据用本地域数据**（不是开源混合集），因为剪枝保的是部署域精度；
- 每轮评测同时跑场景分层指标，弱场景（逆光/草地）掉点超 2 倍均值则回退一轮；
- 检测头与分割头共享的 backbone 剪枝时，两个任务的梯度都参与 Taylor 重要性（Torch-Pruning 自定义 importance 即可）；
- 最后一层/检测头的通道尽量保守剪（对精度最敏感），给分组设 `ignored_layers`。

## 3. 稀疏率搜索

- 扫描稀疏率 {20%, 30%, 40%, 50%, 60%}，画"精度-FLOPs"帕累托曲线；
- 选择满足精度约束的最大稀疏点（经验上 YOLO-s 级模型 40~50% 通常安全）。

## 4. 评价

| 验证项 | 方法 | 达标线 |
|---|---|---|
| 精度 | 金标准 test 集 mAP/mIoU + 分层 | 相对基线 mAP≥-2，mIoU≥-3 |
| 结构合法性 | 导出 ONNX，onnxruntime GPU/CPU 推理数值对齐（与 PyTorch 输出 max err <1e-4） | 通过 |
| 重要性准则对比 | L2 vs Taylor 同稀疏率对照（消融） | 报告差异 |

## 5. 风险与对策
- 恢复训练不收敛/掉点多：减小单轮剪枝率、增加轮数；或对 backbone 分层设置稀疏率（浅层少剪、深层多剪）；
- Torch-Pruning 对自定义多任务头分组报错：为双头 YOLO 写自定义 `DependencyGraph` 插件或退而求其次剪 PP-LiteSeg 独立模型路线；
- 剪枝与量化叠加效应：本阶段产出的模型立即做一次 PTQ 冒烟测试（见 05），提前暴露叠加掉点。
