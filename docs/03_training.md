# 03 · 模型选型与训练

## 1. 选型

| 任务 | 主选 | 备选 | 理由 |
|---|---|---|---|
| 检测 | **YOLOv11-s**（640 输入） | RT-DETR-R18 | YOLOv11 在 X5 工具链支持成熟、剪枝生态（Torch-Pruning 兼容）好；RT-DETR 精度上限高但 Transformer 在 BPU 上算子风险更大 |
| 分割 | **YOLOv11n-seg**（多任务头，与检测共用一个模型） | PP-LiteSeg 独立模型 | 首选"单模型双头"：一次前向同时出检测框与可行驶 mask，端侧调度最简单、总延迟最低 |

> 最终交付形态：**一个 YOLOv11-seg 模型**，检测 12 类 + 分割 4 类共享 backbone/neck，两个 head 输出。这最贴近地平线方案商的量产做法。

## 2. 数据融合策略（开源 + 本地）

两阶段训练：
1. **阶段一 · 域预训练**：开源数据（RELLIS-3D/RUGD 映射后的分割 + KITTI/BDD 检测子集）混合，只训分割/检测对应头，学习通用"地面/障碍"先验；
2. **阶段二 · 本地域微调**：本地数据为主（≥70%），开源数据降采样混入（≤30%）防灾难性遗忘；金标准 test 集绝不参与。

类别不均衡处理：
- 长尾类（wire/pit/step_edge）加权采样 + copy-paste 增广（把长尾目标贴到空旷帧，同步贴 mask）；
- 检测 loss 按类频率倒数加权（上限 clamp 防爆炸）。

增广（只对训练集）：HSV 抖动、随机缩放/平移/Mosaic、轻度运动模糊（模拟车载）、雨滴/雾合成（可选）。**验证/测试集不做破坏性增广**。

## 3. 多任务训练设计（检测 + 分割双头）

### 3.1 模型结构与监督流

```
Input 640×640
  └─ Backbone（共享，梯度来自两个任务之和）
       └─ Neck/PAN（共享）
            ├─ Detect Head → box/cls/dfn loss ──┐
            └─ Segment Head(Proto+掩码系数) → mask loss ──┤
                                                        ▼
                                    L = λ_det·L_det + λ_seg·L_seg
```

ultralytics 的 YOLOv11-seg 原生就是这个结构：分割采用 Proto 系数方式（head 输出每框 K 个掩码系数，与共享 Proto 卷积组合出实例 mask），对"可行驶区域"这种语义分割任务，做法是**给每个连通域当作一个"实例"标注**，推理时按类别合并 proto mask 即得到语义可行驶区域。这样无需改动模型结构，工具链兼容性最好。

### 3.2 数据层面的多任务组织

关键现实问题：**不是每帧都有两种标注**（开源分割集没有检测框、开源检测集没有 mask、本地数据两者都有）。

- 数据加载器统一带 `task_mask` 标记：`{det, seg}` / `{det}` / `{seg}`；
- 一个 batch 内按任务可用性分桶（`batch_sampler` 按标注类型组 batch），避免同 batch 混杂导致 loss 项缺省抖动；
- 某任务在 batch 内全缺时，其 loss 置 0 且该步的 λ 固定（不参与动态调权，防止权重漂移）；
- 本地双标数据是"桥接域"：训练曲线上监控它同时约束两个任务的梯度一致性。

### 3.3 损失平衡策略（三级递进，逐级验证）

| 级别 | 方法 | 说明 |
|---|---|---|
| L1 基线 | 固定权重：`λ_det=1, λ_seg=1`（内部子权重用 ultralytics 默认） | 先跑通，作为对照 |
| L2 手动调参 | 网格搜索 λ_seg ∈ {0.5, 1, 2, 4}，以 val 上 **两任务各自的短板指标**（长尾类 AP 与 drivable IoU）选点 | 检测通常主导共享特征，λ_seg 往往需要上调 |
| L3 动态权重 | 不确定度加权（Kendall 2018）：每个任务加可学习的 `log σ_t`，`L = Σ (1/2σ_t²)·L_t + log σ_t`，端到端学 | 代码侵入小（自定义 loss 模块），若 L2 两任务互挤（一升一降 >1 个点）则启用 |

### 3.4 梯度冲突处理（进阶，按需启用）

若 L3 后仍出现"分割涨、检测掉"的跷跷板现象：
- **PCGrad**：两任务梯度余弦为负时做投影消解冲突（批级实现，开销小）；
- 或退一步做**分阶段解耦**：前 50 epoch 冻结 segment head 只训检测 → 解冻联合微调 50 epoch。作为兜底方案，实现成本最低。

### 3.5 训练监控（多任务特有）

除了单任务的 mAP/mIoU 曲线，额外记录：
- 每任务 loss 与梯度范数（`‖g_det‖, ‖g_seg‖`）随 step 曲线——诊断任务竞争的直接证据；
- 共享 backbone 各 stage 的逐层梯度余弦相似度（抽查若干 step）；
- 双任务联合 vs 单任务各自的 val 指标差：联合训练对检测的代价（-Δ mAP）应在 2 个点以内，否则说明分割头在抢占容量，需回退 λ 或加大模型规模（s → m）。

## 4. 训练配方（基线）

- 输入 640×640（保持宽高 letterbox），bs 64（等效），cosine lr，AdamW/SGD-momentum 均可（ultralytics 默认 SGD），epoch：阶段一 50、阶段二 100（早停 patience 20）；
- 损失：检测 box/cls/dfn + 分割 mask loss（ultralytics 自带多任务权重，`box:7.5 cls:0.5 dfl:1.5 seg:1.0` 起步，长尾类不达标再调）；
- 超参实验用 val 集，最终一次 test 集评测。

## 5. 评价指标与达标线

| 指标 | 目标 |
|---|---|
| 检测 mAP@0.5（总体） | ≥0.60（FP32 基线） |
| 长尾类单类 AP@0.5 | wire ≥0.35，pit ≥0.30 |
| 分割 mIoU | ≥0.75，其中 drivable_road IoU ≥0.85（安全关键） |
| 推理速度（X5 实测） | 端到端 ≥20 FPS（与 06 联合验收） |

评测必须**场景分层**报告（草地/室内/逆光/黄昏…），防止总体指标掩盖弱场景。另做失败案例分析（FP/FN top 原因归类），回流到数据补采与增广策略。

## 6. 消融实验矩阵（体现工程严谨性）

1. 仅本地数据 vs 开源预训练+微调 vs 混合训练（验证开源数据增益）；
2. 预标注来源：大 VLM 标注 vs 小 VLM 标注 vs 人工精标（同帧数）→ 得出"预标注质量-最终精度"关系；
4. 多任务策略：固定权重 vs 不确定度加权 vs 分阶段解耦（对照 3.3/3.4）；
5. copy-patch 长尾增广开/关。
